## ۱) سیستم تاریکی و دید

### ۱.۱ فلسفه

> **نور = اطلاعات.** هر چیزی که روشن است، دیده می‌شود. هر چیزی که خاموش است، وجود ندارد.

در تاریکی، **هیچ‌کس کسی را نمی‌بیند** — نه بازیکن، نه AI.
استثنا: فاصله‌ی زیر ۲.۵ متر (حس لمس/صدای نفس)، که در GDD v1 هم بود.

### ۱.۲ سه لایه‌ی نور

| لایه | چه کاری می‌کند | هزینه |
|---|---|---|
| **A. نور محیط تیم** | فقط ۰.۰۵ — برای اینکه صفحه سیاه مطلق نشود | صفر |
| **B. چراغ‌قوه‌ها** | منبع اصلی اطلاعات. SpotLight واقعی + کشش کف | ۶ نور حداکثر |
| **C. چراغ‌های اضطراری** | ۳ تا ۵ عدد در نقشه، خیلی کم، فقط برای ناوبری | ۵ نور ثابت |

**قانون نور ۰ (قانون صفر):** اگر نقطه‌ای در هیچ مخروطی نباشد،
`lightLevel = 0.05` است. در این حالت **هیچ AI نمی‌تواند آن را ببیند**،
حتی در ۳ متری. (بازیکن با چشم خودش هم تقریباً چیزی نمی‌بیند.)

### ۱.۳ تابع `lightLevel(point)` — قلب سیستم

```
lightLevel(p) = ambient(0.05)
              + playerCone(p)      // اگر داخل مخروط بازیکن باشد
              + Σ aiCone_i(p)      // برای هر AI با چراغ‌قوه روشن
              + Σ staticLight_k(p) // چراغ‌های اضطراری
```

هر جمله:

```
cone(p) = intensity × shape(dist, angle)
shape = smoothstep(0, 0.15, ndist) × (1 - smoothstep(0.75, 1.0, ndist))   // افت نرم در دو سر
      × (1 - smoothstep(0.5, 1.0, |angle| / halfAngle))                    // لبه‌ی نرم
```

- `intensity`: بازیکن ۱.۰، AI ۰.۸، چراغ ثابت ۰.۴
- `halfAngle`: ۱۸° (باریک‌تر از SpotLight سه‌بعدی، چون در نمای عمود باید تیز باشد)
- `range`: بازیکن ۲۲ متر، AI ۱۴ متر، چراغ ثابت ۸ متر

**اسمی‌سازی:** `lightLevel > 0.22` یعنی «دیده می‌شود».

### ۱.۴ توابع دید

```js
// آیا a می‌تواند t را ببیند؟  (پیاده‌شده در src/vision.js)
function canSee(a, t) {
  const d = dist(a, t);
  if (d < 2.5) return true;                       // ۱) حس نزدیک

  const lit = lightLevel(t.position);             // روشناییِ خودِ هدف
  // ۲) برد مؤثر: یا برد دید ناظر، یا برد «هدفِ روشن» (هر کدام بیشتر)
  const effRange = lit > 0.22 ? Math.max(a.viewRange, 22) : a.viewRange;
  if (d > effRange) return false;

  if (!hasLineOfSight(a, t)) return false;        // ۳) دیوار
  return lit > 0.22;                              // ۴) نور
}
```

**قاعده‌ی «هدفِ روشن» (کشف‌شده در تست):** کسی که چراغش روشن است،
حتی برای ناظرِ چراغ‌خاموش هم از ۲۲ متر دیده می‌شود. بدون این قاعده،
بازیکنِ کاملاً روشن در ۱۰ متریِ بات دیده نمی‌شد — هم غیرواقعی، هم
بازی را بی‌منطق می‌کرد.

**قانون دید ۱:** ترتیب شرط‌ها مهم است. `lightLevel` گران‌ترین است، آخر می‌آید.

**قانون دید ۲:** برد دیدِ AI به نور خودش وابسته است:
- چراغ‌قوه روشن: `viewRange = 16`
- چراغ‌قوه خاموش: `viewRange = 4` (فقط صدا و حس نزدیک)

**قانون دید ۳ (مهم‌ترین):** بازیکن با چراغ‌قوه‌ی خاموش در تاریکی
**هرگز** شلیک‌خور نمی‌شود. تست `test-vision.mjs` این را اثبات می‌کند:
۱۰۰۰ فریم شبیه‌سازی، بازیکن ثابت در تاریکی، صفر گلوله.

### ۱.۵ واکنش به دیدن — نه شلیک فوری

AI پس از دیدن، بلافاصله شلیک نمی‌کند (این «ربات‌وار» است):

| مرحله | مدت | چه می‌شود |
|---|---|---|
| متوجه شدن | ۰.۱۸ تا ۰.۳۲ ثانیه (تصادفی) | فقط می‌چرخد به سمت هدف |
| نشانه‌گیری | ۰.۲ ثانیه | اسلحه بالا می‌آید |
| شلیک اول | بعد از ۰.۴ ثانیه | دقت ۶۰٪ |
| شلیک دوم به بعد | طبق نرخ سلاح | دقت به ۸۵٪ می‌رسد |

اگر هدف از دید خارج شود (نور خاموش/پشت دیوار): **۱.۵ ثانیه** حافظه،
بعد رها می‌کند. اگر دوباره دید، تأخیر واکنش نصف می‌شود.

### ۱.۶ سکوت و صدا

- دویدن: صدا تا ۱۶ متر → AI بدون دیدن هم «حدس» می‌زند (فقط جهت، نه هدف)
- راه رفتن آرام (Shift): ۴ متر
- ایستاده: ۰ متر

4. **بازوبند قرمز** روی شانه‌ی چپ — تنها رنگ اشباع
5. **رنگ:** خاکی/قهوه‌ای `#5c5346` + جلیقه `#332e26`

**تفاوت از بالا در ۰.۲ ثانیه:**
- سوات = دایره‌ی براق + مستطیل‌های افقی + سرمه‌ای

## ۳) قوانین انیمیشن و حرکت AI

### ۳.۱ قوانین انیمیشن (تکرار GDD v1 + سه قانون جدید)

قوانین A1–A12 در `docs/GDD.md` بخش ۳ معتبرند. سه قانون جدید:

| # | قانون | چرا |
|---|---|---|

| A15 | **در حالت نشانه‌گیری، تنه رو به هدف و پاها رو به حرکت** (additive در فاز ۲) | حرکت جانبی طبیعی‌تر |

### ۳.۲ حرکت AI — مشکل و راه‌حل

**مشکل فعلی:**
```js
a.g.position.x += Math.sin(ang) * step;   // بدون شتاب، بدون توقف
```
نتیجه: رباتی که با سرعت ثابت می‌لغزد و می‌ایستد.

**راه‌حل — مدل حرکت با شتاب و اصطکاک:**

```
سرعت هدف: vTarget = direction × desiredSpeed
شتاب:     v += (vTarget - v) × (1 - exp(-k × dt))      // k = 6 توجه، k = 10 توقف
موقعیت:   pos += v × dt
```

- `desiredSpeed`: ۴.۵ m/s (دویدن)، ۱.۸ (راه رفتن آرام)، ۰ (توقف)
- AI قبل از شلیک **۰.۲ ثانیه** سرعتش را کم می‌کند (توقف انسانی)
- AI هر **۰.۸ تا ۱.۶ ثانیه** یک «تصمیم» می‌گیرد (نه هر فریم)

**الگوی حرکت (behavior tree کوچک):**

```
اگر دشمن دیده شد:
    اگر فاصله > برد مؤثر → نزدیک شو (با کاور)
    اگر فاصله < برد مؤثر → توقف، نشانه‌گیری ۰.۲s، شلیک
    اگر آسیب دید → عقب‌نشینی جانبی ۱.۵ ثانیه، بعد دوباره
اگر دشمن دیده نشد:
    به سمت آخرین موقعیت شناخته‌شده برو
    اگر ۳ ثانیه چیزی نبود → گشت در نقطه‌ی بمب
```

**گشت (patrol):** AI بین ۳ تا ۵ «نقطه‌ی علاقه» جابه‌جا می‌شود (نقاط بمب،
راهروها، پشت کاورها). تصادفی نیست — طراحی‌شده است.

### ۳.۳ تست‌های الزامی

`scripts/test-ai.mjs` باید این ۵ چیز را بسنجد:
1. AI در تاریکی به بازیکن شلیک نمی‌کند (صفر گلوله در ۱۰۰۰ فریم)
2. AI وقتی چراغ‌قوه‌ی بازیکن روشن است، شلیک می‌کند
3. سرعت حرکت AI هرگز از ۴.۸ m/s بیشتر نمی‌شود (بدون تلپورت)
4. تغییر جهت بیش از ۱۲۰° در یک فریم رخ نمی‌دهد (بدون چرخش ناگهانی)
5. پس از ۶۰ ثانیه، AI گیر نکرده (حداقل ۳۰ متر جابه‌جا شده)

## پیوست ج — سه باگ واقعی که تست‌ها پیدا کردند

این سه مورد در بازبینی چشمی دیده نمی‌شدند و فقط با شبیه‌سازی بیرون آمدند:

1. **AI بدون هدف یخ می‌زد.** `updateAI` وقتی تیمی را نمی‌دید، `return` می‌کرد
   بدون هیچ حرکتی. روی نقشه‌ی خالی که تیم‌ها ۴۴ متر از هم‌اند، هیچ‌کس هم‌دیگر
   را نمی‌دید و **کل تیم‌ها تا آخر راند بی‌حرکت می‌ماندند**.
   → راه‌حل: `patrol()` با ۷ نقطه‌ی علاقه.

2. **بازیکنِ روشن از ۱۰ متری دیده نمی‌شد.** برد دید بات به چراغ خودِ بات
   وابسته بود؛ پس باتِ چراغ‌خاموش یک بازیکنِ کاملاً روشن را هم نمی‌دید.
   → راه‌حل: قاعده‌ی `LIT_SIGHT = 22` در `canSee`.

3. **شبیه‌سازی تست، منطق بازی را نداشت.** تست AI بات را حتی بدون دیدن
   هدف به سمت بازیکن می‌بُرد؛ در نتیجه «۲۳ شلیک در تاریکی» گزارش می‌شد
   در حالی که بازی ۰ شلیک می‌کرد. تستِ غلط بدتر از نبودِ تست است.
   → راه‌حل: `stepAI` حالا دقیقاً مثل `updateAI` رفتار می‌کند.
